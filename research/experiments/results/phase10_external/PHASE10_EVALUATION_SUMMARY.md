# Phase 10 External Evaluation Summary

## Scope

Phase 10 evaluates the Aegis authorization gateway against two external evaluation surfaces:

1. An OPA/Rego baseline over the frozen 300-scenario held-out corpus.
2. A naturalistic LLM-agent experiment in which an external model generates tool calls that are submitted to Aegis for enforcement.

This document summarizes the final reported measurements. It is an analysis artifact, not a new benchmark or a replacement for the raw JSON results.

## 1. OPA baseline

Artifact: `research/experiments/results/phase10_external/opa_v2.json`

| Metric | Result |
|---|---:|
| Scenarios | 300 |
| Expected ALLOW | 49 |
| Expected DENY | 251 |
| OPA ALLOW | 49 |
| OPA DENY | 251 |
| Agreement | 300/300 |
| Agreement rate | 100% |
| Disagreements | 0 |

The baseline protocol explicitly treats OPA as evaluating the static policy surface while explicit transaction-state preconditions are supplied by the independent adapter. The result therefore demonstrates consistency with the benchmark's declared policy decisions; it does **not** constitute a proof that OPA is universally equivalent to Aegis or that the benchmark labels are human-independent ground truth.

## 2. LLM-agent evaluation

Final model/provider: `openai/gpt-oss-120b` via Groq.

Final artifact: `research/experiments/results/phase10_external/llm_groq_gptoss120b_naturalistic_v4.json`

| Metric | Result |
|---|---:|
| Cases | 20 |
| Episodes with model-generated tool call | 20/20 |
| Gateway DENY decisions | 17 |
| Gateway ALLOW decisions | 3 |
| Model refusals | 0 |

The 20-case corpus contains 17 adversarial/policy-violating scenarios and 3 legitimate controls. The observed gateway decisions were 17 DENY and 3 ALLOW, matching the intended case split. This should be reported as an exact result for this frozen corpus, not as a general security rate for LLM agents.

For denied requests, the gateway response records `downstream_executed: false`; the experiment therefore evaluates the intended enforcement boundary rather than relying on the model to self-police its tool requests.

## 3. Stateful-context validation

The LLM harness was corrected so that the model controls the proposed operation while benchmark-controlled execution state remains authoritative. In particular, the case `LLM11` contains a prior `payment_created` event for the same transaction. The corrected run supplied that history independently to the gateway and produced:

- model-generated duplicate-create tool call: yes;
- benchmark history supplied: yes;
- history events supplied: 1;
- gateway decision: DENY;
- reason: `state_invalid_transition`;
- downstream execution: false.

This regression is important because allowing the model to omit or rewrite benchmark history would invalidate stateful authorization evaluation.

## 4. Experimental interpretation

The combined evaluation supports a narrower and defensible claim:

> On the frozen evaluation corpora, Aegis consistently enforced the declared authorization policy against both directly supplied benchmark scenarios and tool calls generated by an external LLM, including state-dependent requests, while allowing the included legitimate controls.

The experiments do **not** establish:

- comprehensive security coverage of all possible attacks;
- complete mutation coverage;
- mathematical proof of oracle correctness;
- universal security across LLMs, providers, or deployment environments;
- superiority over OPA in every policy language or deployment configuration.

## 5. Reporting guidance

Do not describe the 17/20 result as an `85% security rate`. The 20 cases were intentionally constructed as 17 adversarial cases plus 3 legitimate controls. The scientifically useful observation is that all 17 adversarial cases were denied and all 3 controls were allowed in this frozen run.

Likewise, the OPA 300/300 result should be described as agreement with the benchmark's declared expected decisions, not as independent human ground truth.
