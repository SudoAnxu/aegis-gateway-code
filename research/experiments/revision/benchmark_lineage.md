# Benchmark Lineage Report

**Generated:** Revision phase, after Phase 10 evaluation freeze.
**Purpose:** Resolve the apparent discrepancy between Phase 8's held-out benchmark (522 cases) and Phase 9's full-corpus held-out (557 cases).

## Summary

The additional 35 cases between the static held-out (522) and the expanded held-out (557) are **stateful sequence cases** added during the Phase 9 corpus expansion. The 522 static cases are a strict subset of the 557 expanded cases — every static case ID is present in the expanded corpus. No cases were removed, regenerated, or replaced.

## What the 35 Additional Cases Are

All 35 additional cases are in the `stateful_sequence` category. These represent multi-step request sequences that test Aegis's state-store enforcement (e.g., duplicate payment detection, invalid state transitions). They were added because the static benchmark contained no stateful test cases, which was identified as a coverage gap in Phase 9.

The stateful cases exercise:
- Duplicate payment creation (state rejects re-execution)
- Invalid refund sequences (refund without prior creation)
- State transition ordering (correct sequence required)

## What the 35 Additional Cases Are NOT

- They are **not** regenerated versions of existing cases.
- They are **not** a different benchmark.
- They do **not** replace or modify any of the original 522 static cases.
- They are **not** hand-written adversarial attacks; they were generated by the same `aegisbench-expand-v3` pipeline.

## Phase 9 300-Case Independent Validation

The 300-case independent validation set (`independent_cases_v3.json`) is a **separate, independently authored** set of cases. It is NOT a subset of either the 522 or 557 held-out corpora. It was constructed independently using the policy contract and labeled by a standalone policy-contract labeler.

## Full-Corpus Oracle Cross-Check

Phase 9 performed a full-corpus cross-check of 1,508 scenarios (951 development + 557 held-out, expanded) against a structurally independent second oracle. Result: 1,508/1,508 agreement (100%).

This cross-check covers both the original 522 static cases (embedded within the 557 expanded) and the 35 additional stateful cases.

## Conclusion

The shift from 522 to 557 represents a **deterministic expansion** that added stateful sequence cases to address a documented coverage gap. The original 522 cases are fully preserved within the 557-case expanded corpus. There is no ambiguity, no case substitution, and no data loss.
